STEP 3. 서버 환경 세팅
────────────────────────────────────────────────────

이하 모든 명령어는 EC2 서버(ubuntu@ip-172-31-39-114) 터미널에서 실행.

[3-1] 패키지 업데이트

    sudo apt update && sudo apt upgrade -y

  - apt update  : 패키지 목록 최신화
  - apt upgrade : 설치된 패키지 최신 버전으로 업그레이드
  - -y          : 모든 확인 질문에 자동으로 yes

[3-2] 필수 패키지 설치

    sudo apt install -y python3-pip python3-venv git nginx ffmpeg

  설치되는 것:
    python3-pip   : pip (Python 패키지 설치 도구)
    python3-venv  : Python 가상환경
    git           : 코드 클론용
    nginx         : 웹 서버 (React 정적 파일 서빙 + 리버스 프록시)
    ffmpeg        : 영상 프레임 추출 및 H.264 재인코딩

[3-3] Node.js 설치 (React 빌드용)
  먼저 nodesource 저장소 등록 후 설치:

    curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
    sudo apt install -y nodejs

  ※ 처음에 위 과정 없이 apt install nodejs 로 설치하면
     v12.22.9 (구버전) 이 설치되고 npm이 없음.
     nodesource를 통해 v20.20.2 설치해야 npm 포함됨.

  설치 확인:
    python3 --version   → Python 3.10.12
    node --version      → v20.20.2
    npm --version       → 10.8.2
    ffmpeg -version     → ffmpeg version 4.4.2

  스왑 메모리 추가 명령어 (참고):
    sudo fallocate -l 4G /swapfile
    sudo chmod 600 /swapfile
    sudo mkswap /swapfile
    sudo swapon /swapfile

STEP 8. nginx 설정
────────────────────────────────────────────────────

nginx: 웹 서버. 아래 두 가지 역할 수행.
  ① 80번 포트로 들어온 요청 처리
  ② /api/ 경로는 FastAPI(8001포트)로 전달 (리버스 프록시)

[8-1] 설정 파일 작성

    sudo tee /etc/nginx/sites-available/default > /dev/null << 'EOF'
    server {
        listen 80;
        server_name _;
        client_max_body_size 500M;

        root /var/www/html;
        index index.html;

        location / {
            try_files $uri $uri/ /index.html;
        }

        location /api/ {
            proxy_pass http://127.0.0.1:8001;
            proxy_set_header Host $host;
            proxy_set_header X-Real-IP $remote_addr;
        }

        location /results/ {
            alias /home/ubuntu/beauty/webpage/backend/results/;
        }
    }
    EOF

  각 설정 의미:
    listen 80              : 80번 포트(HTTP) 수신
    server_name _          : 모든 도메인/IP에 반응
    client_max_body_size   : 업로드 파일 최대 크기 500MB
    root /var/www/html     : 정적 파일 위치
    location /             : React 앱 서빙. try_files로 SPA 라우팅 지원
    location /api/         : /api/로 시작하는 요청은 FastAPI로 전달
    location /results/     : 결과 영상 직접 서빙

[8-2] 설정 문법 검사

    sudo nginx -t

  출력:
    nginx: the configuration file syntax is ok
    nginx: configuration file test is successful
  → 이 메시지가 나와야 정상. 에러 있으면 재시작 불가.

[8-3] nginx 재시작

    sudo systemctl restart nginx


────────────────────────────────────────────────────
STEP 9. FastAPI systemd 서비스 등록
────────────────────────────────────────────────────

systemd: Linux 서비스 관리자.
서비스로 등록하면 서버 재부팅 시 자동 시작, 크래시 시 자동 재시작.

[9-1] 서비스 파일 작성

    sudo nano /etc/systemd/system/beauty.service

  내용:
    [Unit]
    Description=Beauty SMAS FastAPI Server
    After=network.target

    [Service]
    User=ubuntu
    WorkingDirectory=/home/ubuntu/beauty/webpage/backend
    Environment="PATH=/home/ubuntu/beauty/webpage/backend/venv/bin"
    ExecStart=/home/ubuntu/beauty/webpage/backend/venv/bin/uvicorn main:app --host 0.0.0.0 --port 8001
    Restart=always

    [Install]
    WantedBy=multi-user.target

  각 항목 의미:
    User=ubuntu              : ubuntu 계정으로 실행
    WorkingDirectory         : 서비스 실행 디렉토리 (main.py 위치)
    Environment PATH         : venv의 Python/uvicorn을 우선 사용
    ExecStart                : 실제 실행 명령어
    Restart=always           : 크래시 시 자동 재시작

[9-2] 서비스 등록 및 시작

    sudo systemctl daemon-reload   ← 새 서비스 파일 읽기
    sudo systemctl enable beauty   ← 부팅 시 자동 시작 등록
    sudo systemctl start beauty    ← 지금 즉시 시작

[9-3] 상태 확인

    sudo systemctl status beauty

  정상:
    Active: active (running)

[9-4] 이후 코드 업데이트 방법 (파일 수정 후)

    scp -i beauty-key.pem <로컬파일경로> ubuntu@3.35.16.120:<EC2경로>

STEP 11. 트러블슈팅
────────────────────────────────────────────────────

[이슈 A] 413 Request Entity Too Large
  증상: 영상 업로드 시 브라우저 F12에서 413 에러
  원인: nginx 기본 업로드 크기 제한 1MB
  해결: nginx 설정에 client_max_body_size 500M 추가
  참고: nginx가 FastAPI 앞단에서 요청을 먼저 받으므로
        nginx 단에서도 크기 제한 설정 필요

[이슈 B] OpenCV 코덱 미지원으로 프레임 추출 실패
  증상: [Job xxx] 오류: no images found in /tmp/smas_web_xxxx
  원인: inference.py의 extract_frames가 cv2.VideoCapture 사용
        EC2의 opencv-python-headless는 H.264 mp4 코덱 미지원
        → cap.read()가 프레임 읽기 실패 → 추출 파일 0개
  로그 확인:
    sudo journalctl -u beauty -n 50 --no-pager
  해결: extract_frames를 ffmpeg subprocess 방식으로 교체

  변경 전 (OpenCV):
    cap = cv2.VideoCapture(video_path)
    while True:
        ret, frame = cap.read()
        if not ret: break
        cv2.imwrite(...)

  변경 후 (ffmpeg):
    probe_cmd = ["/usr/bin/ffprobe", "-v", "error", ...]
    subprocess.run(probe_cmd, ...)
    cmd = ["/usr/bin/ffmpeg", "-y", "-i", video_path, "frame_%05d.png"]
    subprocess.run(cmd, ...)

  ※ systemd 서비스는 PATH가 제한적이므로 절대경로 사용:
       which ffmpeg  → /usr/bin/ffmpeg
       which ffprobe → /usr/bin/ffprobe

  수정 파일 전송:
    scp -i beauty-key.pem inference.py ubuntu@3.35.16.120:~/beauty/webpage/backend/
    sudo systemctl restart beauty

[이슈 C] MedSAM2 구버전 PNG 미지원
  증상: ffmpeg로 PNG 추출은 성공하는데 여전히 "no images found"
  실시간 모니터링:
    watch -n 1 'ls /tmp/smas_web_* 2>/dev/null'
    → PNG 파일들이 정상 생성됨을 확인
  원인: GitHub의 bowang-lab/MedSAM2 구버전
        sam2/utils/misc.py 가 .jpg/.jpeg만 지원:
          if os.path.splitext(p)[-1] in [".jpg", ".jpeg", ".JPG", ".JPEG"]
        .png 확장자가 목록에 없어서 파일을 찾지 못함
  확인:
    grep -n "png\|jpg\|images found" ~/beauty/MedSAM2/sam2/utils/misc.py
  해결: misc.py에 PNG 확장자 추가

    sed -i 's/in \[".jpg", ".jpeg", ".JPG", ".JPEG"\]/in [".jpg", ".jpeg", ".JPG", ".JPEG", ".png", ".PNG"]/' \
      ~/beauty/MedSAM2/sam2/utils/misc.py

    sudo systemctl restart beauty

STEP 13. EC2 서버 관리
────────────────────────────────────────────────────

[서버 중지] (비용 절약 - EC2 컴퓨팅 요금 중단)
  AWS 콘솔 → EC2 → Instances → 인스턴스 선택
  → Instance state → Stop instance
  ※ EBS 스토리지 요금은 중지해도 계속 발생 (20GB ≈ $2/월)
  ※ Terminate는 영구 삭제이므로 절대 클릭 금지

[서버 재시작]
  AWS 콘솔 → EC2 → Instances → 인스턴스 선택
  → Instance state → Start instance
  ※ Stop/Start 시 Public IP가 바뀜. 새 IP로 접속해야 함.
  ※ IP 고정하려면 Elastic IP 발급 (연결 중엔 무료)

[비용 확인]
  AWS 콘솔 → Billing → Billing and Cost Management
